# LinkedIn ideas

Turns what Eddy works on in Claude Code into LinkedIn post ideas, one markdown file per idea, grouped by content pillar.

## Where things live

- Idea bank (private, not in this repo): `$LINKEDIN_IDEAS_BANK`, default `~/code/pally/content/linkedin-ideas/`. Its `README.md` holds the pillars, voice, keep out rules and file format. Read it before writing or editing ideas by hand.
- `INDEX.md` in the bank is generated by `bin/index.py`. Never edit it by hand.
- State: `~/.claude/linkedin-ideas/` (`last-run`, `seen-sessions.txt`, `digests/<date>/`, `run.log`). Digests hold raw session text; they stay local.

## How it works

1. `bin/digest.py` reads `~/.claude/projects/*/*.jsonl` for sessions started since the last run, skips ones already seen, keeps the user's prompts and each session's last reply, collapses hive worker chats to one line, and writes ~110k character chunks.
2. `bin/run.sh` runs headless `claude -p` with `prompt.md` on each chunk, inside the bank, with only file tools and no MCP servers. Each run adds new ideas, merges repeats into existing ideas (adds sources) and logs to `runs/<date>.md`.
3. `bin/index.py` rebuilds `INDEX.md`; a macOS notification says it's done. Sessions only count as seen once every chunk succeeds.

## Commands

- Pull ideas now: `zsh ~/code/eddys-skills/linkedin-ideas/bin/run.sh --force`
- Backfill a range: `run.sh --force --since 2026-10-04`
- Install the schedule: `zsh ~/code/eddys-skills/linkedin-ideas/setup.sh` (daily check at 10:00; runs when the last run is 3 or more days old; catches up after sleep).
- Change the gap: set `LINKEDIN_IDEAS_EVERY_DAYS` in the plist.

## When Eddy asks for ideas in chat

Read `INDEX.md`, pick by pillar or by what he asks, and open the idea files. When he picks one to draft, set its `status: drafting`; after he posts, `posted`. Drafts follow the voice in the bank README and his rule on dashes.
